PART 1 — AI APPROACHES (per-architecture investigation)
A) CNN-based image classification (ResNet, VGG, custom CNNs)
What it does: Assigns a single class label to a whole image (or a cropped region).
How it works: Stacked convolution + pooling layers learn hierarchical visual features; a final dense/softmax layer outputs class probabilities.
Task type: Classification only (one label per image). Not detection or segmentation on its own.
Multiple objects: No — a plain classifier assumes one dominant object per frame. It cannot localise or separate multiple items in a cluttered tray. This is a key limitation for your "multiple waste objects in the same image" requirement.
Real-time: Yes if lightweight; large CNNs (ResN50, VGG16) are heavier.
Accuracy: High on clean, single-object medical waste images. A Nature Scientific Reports study (2022) built an 8-class medical waste classifier (gauze, gloves, infusion bags/bottles/apparatus, syringe needles, tweezers, syringe). Source: https://www.nature.com/articles/s41598-022-06146-2
Custom dataset needed: Yes for biomedical categories, but ImageNet-pretrained backbones transfer well and reduce data needs.
Suitability for SIH26115: Useful as a second-stage verifier (classify an already-isolated item) but insufficient alone for a tray of mixed waste.
B) YOLO-family object detection (YOLOv5/v8/v11)
What it does: Single-pass ("you only look once") detection — bounding boxes + class labels for many objects at once.
How it works: One CNN predicts boxes and class probabilities directly across a grid; no separate region-proposal stage → fast.
Task type: Object detection (newer versions also offer segmentation and classification variants).
Multiple objects: Yes — core strength; detects many items per frame. Directly addresses your "multiple objects in the same image" and "classification before segregation" needs.
Real-time: Yes — the fastest mainstream family; nano variants target edge.
Accuracy (medical waste evidence):
Hybrid YOLOv8+CNN reported accuracy 0.88 / F1 0.86 (MDPI 2025) — https://www.mdpi.com/2673-4591/84/1/82
A YOLOv11-based framework (SlideLoss + channel attention) built explicitly with Single-Class and Multi-Class instance detection subsets for medical waste (ScienceDirect, 2025) — https://www.sciencedirect.com/science/article/abs/pii/S0952197625034980
YOLOv8s baseline mAP@50 = 0.621 in one waste study (MECS) — https://www.mecs-press.org/ijigsp/ijigsp-v17-n6/v17n6-1.html
Hardware/compute: Nano/small variants run on Jetson well; run slowly on Raspberry Pi CPU (see hardware section).
Training/dataset: Needs annotated bounding boxes (more labeling effort than classification). Many pretrained weights available; medical-waste Roboflow datasets exist (see datasets).
Suitability: Very strong candidate — but not automatically the best. Its weakness is overlapping/occluded items where bounding boxes overlap heavily; segmentation may be needed there.
C) SSD (Single Shot MultiBox Detector) / SSD-MobileNet
What it does: Single-shot detection using multi-scale feature maps.
How it works: Predicts boxes at several feature-map resolutions → good coverage of scales/aspect ratios; end-to-end trainable.
Task type: Object detection. Multiple objects: yes.
Real-time: Yes; SSD-MobileNet / SSDLite-MobileDet are among the lightest detectors and are common on edge/TPU. Benchmarked on Raspberry Pi + Coral TPU (arXiv 2409.16808) — https://arxiv.org/html/2409.16808v1
Accuracy: Generally below YOLO/Faster R-CNN on small objects (needles, thin IV tubes may be missed). The classic Google speed/accuracy survey shows SSD strong on larger objects, weaker on small ones — https://arxiv.org/abs/1611.10012
Suitability: A viable lightweight detector for Raspberry-Pi-class hardware, but small-object weakness is a concern for needles/syringes.
D) Faster R-CNN
What it does: Two-stage detector — region proposals then classification/refinement.
How it works: A Region Proposal Network proposes candidate boxes; a second head classifies and refines them.
Task type: Object detection (basis for Mask R-CNN segmentation). Multiple objects: yes.
Real-time: No — two-stage design is accurate but slow; poorly suited to a moving/real-time mobile unit.
Accuracy: Historically among the highest, especially small objects.
Hardware: Heavy — realistically needs a GPU; not a good edge fit.
Suitability: Useful as an accuracy reference/baseline during R&D, not as the on-board deployment model.
E) EfficientDet (D0–D7 / EfficientDet-Lite)
What it does: Scalable detector using BiFPN feature fusion + compound scaling.
Task type: Object detection. Multiple objects: yes.
Real-time / edge: EfficientDet-Lite variants target edge/TPU and are benchmarked on Raspberry Pi (arXiv 2409.16808). Good accuracy-per-FLOP.
Accuracy: Strong efficiency/accuracy trade-off; competitive with YOLO at similar compute.
Suitability: A legitimate YOLO alternative worth benchmarking on your target board — do not overlook it.
F) MobileNet (V2/V3/V4) — lightweight classification backbone
What it does: Efficient CNN classifier/backbone using depthwise-separable convolutions.
Task type: Classification (also a backbone inside SSD-MobileNet detectors).
Edge: Excellent — designed for mobile/embedded. In a waste study, MobileNetV2 hit 94.4% classification accuracy (beating EfficientNet's 87.8%) — https://www.mecs-press.org/ijigsp/ijigsp-v17-n6/v17n6-1.html. MobileNetV3 noted as best accuracy/efficiency balance (arXiv 2505.03303) — https://arxiv.org/html/2505.03303v1
Suitability: Strong candidate for the classification stage or as a detector backbone on constrained hardware.
G) EfficientNet / EfficientNetV2 / EfficientNet-Lite
What it does: Classification family using compound scaling of depth/width/resolution.
Task type: Classification.
Accuracy/edge: EfficientNetV2 consistently highest accuracy among lightweight families in one comparison; EfficientNet-Lite0 reached 93.99% on a compact waste study with a small footprint — https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2026.1804734/full and https://arxiv.org/html/2503.21208v1
Suitability: Strong classification candidate; Lite variant for edge. Slightly heavier than MobileNet at comparable accuracy in some tests.
H) Vision Transformers (ViT / Swin)
What it does: Treats image as sequence of patches; self-attention models global relationships.
Task type: Classification (DETR/Swin variants do detection/segmentation).
Accuracy: Very high when large-scale pretraining and ample data are available.
Key limitations for you:
Need very large training data or heavy pretraining (Towards Data Science; PatSnap) — https://towardsdatascience.com/vision-transformers-vit-explained-are-they-better-than-cnns/
Compute/memory-intensive; hard to deploy on edge (self-attention scales O(N²)) — https://www.lightly.ai/blog/vision-transformers-vit
CNNs remain more data-efficient and faster for small datasets/edge (Roboflow; ScienceDirect 2026) — https://blog.roboflow.com/vision-transformer-vs-cnn-for-detection/
Suitability: Likely poor fit for a small custom biomedical dataset on embedded hardware. Note it, but it is not a front-runner for a mobile prototype.
I) Image segmentation (semantic + instance: Mask R-CNN, YOLO-seg)
What it does: Pixel-level masks. Instance segmentation traces each object's outline, even overlapping ones.
Why relevant: Handles occluded/overlapping waste better than bounding boxes — directly relevant to a mixed waste tray. Ultralytics/Think Autonomous note masks separate overlapping instances — https://www.ultralytics.com/blog/what-is-instance-segmentation-a-quick-guide
Trade-offs: Mask R-CNN is accurate but slow/heavy; YOLO-seg offers real-time segmentation and is the more edge-realistic option.
Suitability: Worth testing if bounding-box detectors struggle with tangled items (e.g., IV tubes wrapped around syringes).

Dataset conclusion: Small, on-topic biomedical waste datasets do exist (mostly Roboflow + GitHub, 1.5k–2k images, colour/category-labelled sharps, gloves, IV sets, etc.), but there is no large, authoritative, standardised public biomedical-waste dataset matching Indian CPCB colour categories (yellow/red/white/blue) at scale. Existing sets are small, of varying quality, and not aligned to CPCB's four-bin scheme.

Custom dataset feasibility: Realistic and likely necessary. Recommended approach for your team to evaluate:

Collect images under proper permissions (hospital/CBWTF partnership) with IEC/ethics clearance — biomedical waste is sensitive and regulated.
Label to CPCB colour categories (yellow/red/white-translucent/blue) plus item type, so AI output maps directly to segregation bins.
Augment (lighting, angles, occlusion, wet/soiled items) since real waste is contaminated/deformed — a documented failure mode (IJEETR) — https://ijeetr.com/index.php/ijeetr/article/download/812/759/1589
Start by fine-tuning a pretrained model on public Roboflow sets, then extend with your own images (transfer learning reduces data needs).

Edge vs Cloud (for a mobile autonomous unit):

Edge favours autonomy, offline operation, low latency, data locality (patient/biomedical privacy). Cloud favours scale but needs constant connectivity and adds latency — https://reemanbot.com/edge-ai-in-autonomous-mobile-robots-on-device-inference-explained/ ; https://embodiedaiinsights.com/explainers/where-robot-intelligence-should-run
Recommendation direction: on-board edge inference for real-time classification/segregation; optional cloud sync for logging, traceability dashboards, and model retraining — a hybrid deployment, not cloud-dependent operation.
Hardware honesty note: Don't pick Jetson just because it's popular, or Pi just because it's cheap. The right choice depends on whether your unit scans items statically (Pi/Pi+accelerator may suffice) or must detect continuously while moving (Jetson Orin class). Battery-electric autonomy makes power draw a real selection criterion.

PART 5 — AI-ONLY vs HYBRID (CV + sensors + rules)
Why AI alone is risky for biomedical waste:

Real waste is occluded, damaged, contaminated, soiled → visual classification becomes unreliable (IJEETR) — https://ijeetr.com/index.php/ijeetr/article/download/812/759/1589
Visually similar items get confused; feature representations aren't always discriminative (Nature Sci Reports 2026) — https://www.nature.com/articles/s41598-026-43827-8
Misclassifying infectious sharps into the wrong bin is a safety/regulatory failure, not just an accuracy metric — the cost of error is high.
Evidence for hybrid / sensor fusion:

Sensor fusion overcomes single-sensor limits, reducing uncertainty (ResearchGate) — https://www.researchgate.net/publication/373081984
Vision + RFID waste sorting automation — https://www.researchgate.net/publication/387002978
Vision-guided robotic sorting outperforms sensor-only or manual — https://www.researchgate.net/publication/395566841
Real-world vision-robotic sorting reached ~81.8% accuracy — https://www.mdpi.com/2813-0391/4/2/16 (i.e., pure vision leaves a meaningful error margin)
Hybrid inputs to combine with AI vision for SIH26115:

Weight sensing (load cells): distinguishes heavy glass/vials vs light cotton/gloves; validates AI class; also serves your weight-detection/traceability requirement.
Proximity/IR/ToF: confirms item presence before capture/actuation; triggers scan.
RFID / barcode / QR: identifies pre-tagged bags/containers and drives traceability (matches your digital tracking scope).
Colour recognition: cross-checks CPCB colour category (bag/bin colour) against AI class.
Metal detection (optional): flags sharps/metal instruments.
AI-only vs Hybrid — summary

AI-only (vision)	Hybrid (vision + sensors + rules)
Accuracy on clean items	High	High
Robustness to occlusion/contamination	Weak	Strong (sensors compensate)
Safety/failsafe on misclassification	Low (single point of failure)	High (rule can override — e.g., "if sharp/metal detected → route to sharps regardless")
Complexity/cost	Lower	Higher (fusion logic, integration)
Traceability integration	Partial	Native (RFID/QR/weight logging)
Fit for SIH26115	Insufficient alone	Recommended direction
Conclusion: For a safety-critical, regulated biomedical waste system, a hybrid approach (AI vision + weight/proximity/RFID/colour sensing + predefined decision rules) is more appropriate than AI alone. A rule layer provides a failsafe: when AI confidence is low or sensors disagree, default to the safest bin (e.g., treat as infectious/sharps). This is a design recommendation for your team to validate, not a final decision.

PART 7 — AI TECHNOLOGIES WORTH FURTHER INVESTIGATION
No final model is declared. The strongest candidates for your team to test:

YOLO nano/small (v8 or v11) on Jetson — best-documented real-time, multi-object detector for medical waste; handles "multiple objects + classify before segregate" directly. Test small-object recall on needles.
SSD-MobileNet / EfficientDet-Lite on Raspberry Pi + Coral/Hailo accelerator — the low-power, low-cost path; matters for battery-electric autonomy. Test whether accuracy on sharps is acceptable.
MobileNetV3 / EfficientNet-Lite as a second-stage classifier — pair with a detector: detector localises, lightweight classifier confirms class + CPCB colour category.
YOLO-seg (instance segmentation) — evaluate only if bounding-box detectors fail on overlapping/tangled waste (IV tubes, mixed trays).
Hybrid AI + sensor-fusion + rule layer — treat this as an architecture to test, not a single model: vision + weight + proximity + RFID/QR + colour, with a failsafe decision layer.
Deliberately lower priority: Faster R-CNN and Mask R-CNN (too slow/heavy for on-board real-time — keep as accuracy baselines), and Vision Transformers (too data-hungry and compute-heavy for a small custom dataset on embedded hardware).

What your team should test against before deciding: actual dataset size/quality, target board (Pi vs Jetson) and its power budget, required FPS (static scan vs moving detection), accuracy floor for sharps safety, and prototype cost.
